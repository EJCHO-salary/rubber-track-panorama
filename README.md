# 러버트랙 전개 사진 백엔드

현재 두 촬영 세트에서 실행한 로컬 프로토타입입니다. 원본의 실제 표면을 사용하며, 생성형 이미지나 결함 지우기는 사용하지 않습니다.

동료 개발자를 위한 코드 구조, API 계약, 알려진 한계와 다음 작업은 [개발 인수인계](docs/HANDOFF.ko.md)에 정리했습니다.

## 사용자 입력

- 트랙 폭(mm): 필수
- 피치(mm): 필수
- 전체 링크 수: 선택. 빈 문자열 또는 생략은 동일하게 처리합니다.
- 촬영 사진: 촬영 순서대로 업로드합니다. 시작점·끝점 번호는 입력하지 않습니다.

링크 수를 생략하면 확인 가능한 사진 범위를 처리합니다. 첫·마지막 관측의 같은 표면이 확인되면 피치 이동의 정수 합으로 한 바퀴를 추정하고, 재촬영된 구간을 제거합니다. 폐합을 확인하지 못하면 부분 전개도를 내보내며 전체 제품이라고 표시하지 않습니다. 링크 수를 입력해도 부족한 사진을 반복하거나 빈 표면을 생성하지 않습니다. 실제 확인된 폐합 링크 수와 입력이 다르면 검토 대상으로 거절합니다.

## 실행

Python 3.12 / Windows PowerShell을 기준으로 검증했습니다. 저장소 루트에서 실행하세요.

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
.venv/Scripts/python.exe -m uvicorn track_unwrap.api:app --host 127.0.0.1 --port 8765
```

브라우저에서 <http://127.0.0.1:8765>를 열고 사진을 업로드합니다. API 문서는 `/docs`에서 확인할 수 있습니다. 로컬 데모이며 공개 배포용 인증·다중 사용자 격리는 포함하지 않습니다.

저장소에는 코드·테스트·문서만 포함합니다. 원본 사진 `ref_img/`, 생성 결과 `output/`, 가상환경 `.venv/`는 Git에서 제외했습니다. 샘플을 재현하려면 원본을 별도로 전달받아 아래 위치에 넣고 CLI를 실행하세요. 결과가 생성되면 웹 화면에서도 두 샘플을 전환할 수 있습니다.

```text
ref_img/
  11.jpg ... 15.jpg       # case1: 폭 450 / 피치 86
  case2/
    20250807_*.jpg         # case2: 폭 230 / 피치 48, 12장
```

CLI:

```powershell
.venv/Scripts/python.exe -m track_unwrap --input ref_img --output output/result --width-mm 450 --pitch-mm 86
.venv/Scripts/python.exe -m track_unwrap --input ref_img/case2 --output output/case2 --width-mm 230 --pitch-mm 48
```

선택 인수: `--total-links 72`, `--pixels-per-mm 5`. 사진 이름은 숫자를 인식하여 정렬합니다. API는 multipart의 사진 순서를 사용합니다.

## 처리 방식

1. EXIF 방향 정리와 가로 촬영 회전.
2. 길이 방향으로 지속되는 경계에서 제품의 양쪽 외곽 검출. 배경이 많이 보이는 촬영은 휘어진 끝부분 대신 직선 구간을 우선 사용.
3. 중앙 반복 구조에서 피치 기준점 검출, 약한 기준점은 주변 피치 간격과 국소 영상 근거로 보완.
4. 양방향 SIFT 대응과 피치 단위 이동량의 합의로 동일한 표면 식별. 근거가 부족하거나 이동 방향이 불일치하면 거절.
5. 양쪽 외곽·중앙선·피치 기준점으로 정면뷰 좌표를 구성. 사진 간 양쪽 표면 대응점으로 완만한 기하 보정량을 공동 추정합니다. 좌우 경계는 출력 폭의 0%/100%, 중앙은 50%에 고정하고 피치 순서가 뒤집히지 않게 제한합니다.
6. 기준 외곽과 피치 격자에 재표본화. 폭은 `width_mm × pixels_per_mm`, 피치는 `pitch_mm × pixels_per_mm`로 정규화. 배경이 많이 보이는 경우 전경 분할로 외곽을 추가 정밀화합니다.
7. 저주파 조명 편차를 제한적으로 보정하고, 균열·돌기 모서리를 피하는 연결 경로를 구해 multiband 합성.
8. 폐합이 검증되면 누적 위상 오차를 분산 보정하고 동일 피치 위상에서 한 바퀴만 출력.

돌출 표면과 깊은 중앙 구조를 강제로 맞추는 조밀한 변형은 최종 합성에서 사용하지 않습니다. 이 방식은 시차를 줄이려다 실제 균열과 돌기를 휘게 만들 수 있기 때문입니다.

## 결과

- `output/result/`: 폭 450mm / 피치 86mm / 5장. 10,892 × 2,250px, 확인된 촬영 구간의 부분 전개도.
- `output/case2/`: 폭 230mm / 피치 48mm / 12장. 17,280 × 1,150px, 72링크 추정. 시작·끝 위치를 입력하지 않고 폐합을 확인하여 중복을 제거한 결과.
- `panorama.png`: 무손실 한 장 결과.
- `panorama.jpg`, `preview.jpg`: 보기용 결과.
- `review.jpg`: 같은 결과를 읽기 편하게 4구간으로 나눈 검토용 이미지. 다운로드 PNG는 한 장입니다.
- `quality_report.json`: 대응점 수, 연결 이동량, 폐합, 출력 크기, 연결 경로.
- `provenance.json`: 출처와 기하 보정 정보.
- `debug/`: 검출 외곽·중앙선·피치, 사진별 정면 보정 결과, 연결 전 겹침 비교.

case2의 표면 대응점 7,781개에 대한 중앙값 오차는 보정 전 0.04096피치에서 보정 후 0.01606피치로 감소했습니다. 이는 보정에 사용한 대응점의 적합 오차이며, 독립적인 치수 정확도 검증값은 아닙니다.

실제 링크 수에 대한 독립적인 실물 측정값은 제공되지 않았습니다. case2의 링크 수는 영상의 반복 구조와 폐합으로 추정한 값입니다.

## 검증

```powershell
.venv/Scripts/python.exe -m pytest -q
```

23개 검사가 통과했습니다. 링크 수 생략/빈 값, 잘못된 규격, 정답이 알려진 합성 사진의 이동량, 특징 없는 사진의 거절, multipart 입력과 파일 경로 제한, 기하 보정 후 외곽·중앙선 유지와 뒤집힘 방지를 검사합니다. 실제 샘플은 결과와 연결부 확대 이미지를 별도로 확인합니다.

실제 case2 사진 12장을 링크 수 빈 값으로 API에 업로드하여 비동기 처리 완료와 PNG·4구간 검토 이미지 다운로드까지 확인했습니다. 두 사례의 원본을 전달받은 뒤 서버가 실행 중인 상태에서 `python analysis/smoke_api.py`로 재현할 수 있습니다. 실행 결과 기록 `analysis/api_smoke_result.json`은 로컬에서 생성하며 Git에서 제외합니다. 최초 분석 당시 해시와 비교하여 case1 원본 파일도 변경되지 않았음을 확인했습니다.

## 적용 범위

현재 검출기는 화면 중앙에 하나의 트랙이 있고, 중앙에 규칙적인 반복 구조가 보이는 두 사례를 기준으로 개발했습니다. 가로 또는 세로 방향, 충분한 중첩, 양쪽 외곽과 초점이 필요합니다. 임의의 사선 촬영·가려진 외곽·다른 패턴·순서가 뒤섞인 사진에 대한 범용 인식 성능은 아직 검증하지 않았습니다.

사진의 렌즈 보정 프로필이나 깊이 측정값은 제공되지 않았습니다. 결과는 명목 폭·피치를 맞춘 시각적 전개도이며, 마모·변형의 정밀 치수 측정 자료는 아닙니다. 원본에 있는 조명 차이·그림자·먼지·균열은 일부 남습니다. 보이지 않는 면을 생성하지 않습니다.
