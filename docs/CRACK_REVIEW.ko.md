# 크랙 후보 검토 초안

러버트랙에서 **크랙**은 고무 표면이나 트레드 밑동에 생긴 선형 균열로 취급합니다. 브리지스톤 사용 설명서는 트레드 밑동의 작은 오존 균열과 굽힘 피로로 인한 밑동 균열을 구분하며, 철심·케이블 노출 여부는 별도로 확인하도록 합니다. [브리지스톤 트랙 설명서](https://www.bridgestone.com/products/diversified/rubbertrack/pdf/Tracks-Operating-Manual-USpdf.pdf)

**청크(chunking)**는 고무 덩어리가 표면에서 뜯겨 나간 상태이고, **칩(chipping)**도 표면 조각 손실을 설명할 때 사용됩니다. 제조사 자료는 두 표현을 함께 다루기도 하므로 두 용어 사이에 공통으로 인정되는 크기 경계가 있다고 가정하지 않습니다. 현재 검출기는 사진에서 어둡고 연속된 손상 후보를 제안하며, 사용자가 **청크·티어·칩앤컷** 중 유형을 지정합니다. 자동 유형 판정이나 깊이 판정은 하지 않습니다. [Trackman 용어집](https://www.cisinc-usa.com/wp-content/uploads/Rubber_Track_Warranty_Guide.pdf), [브리지스톤 손상 사례](https://www.bridgestone.com/products/diversified/rubbertrack/pdf/Tracks-Operating-Manual-USpdf.pdf)

## 탐색과 검토

1. 전개 사진을 그레이스케일로 변환하고 영역 마스크의 작업 해상도로 축소합니다. 분류용 마스크가 기본 섹션으로 채운 빈 곳은 제외하고, 사용자가 그린 도형을 반복·배치한 `group_*_authored.png` 안에서만 검출합니다. 두 크기의 black-hat 필터는 국소 대비를 측정하는 보조 신호로만 사용합니다.
2. 사진에서 측정한 피치 기준점을 사용해 두 피치 패턴의 중앙값을 만들고, 같은 위치에서 반복되는 어두운 형상 경계를 억제합니다.
3. 원본 그레이스케일 값이 충분히 어두운 픽셀만 연결하고, 그 안에 연속된 거의 검은 핵심부가 있는 후보를 남깁니다. 영상 노출 차이를 고려해 낮은 밝기 백분위를 기준으로 삼되 상한을 둡니다. 밝은 분필 표시 바로 옆은 억제합니다. 후보마다 윤곽 다각형, 표시 면적(mm²), 영역 ID, 영상 점수, 추정 길이를 저장합니다. 표시 면적은 영상 분할 결과의 면적으로 실제 결손 면적이나 깊이와 같지 않습니다.
4. 자동 후보는 **미검토**로 시작합니다. 사용자는 윤곽을 클릭하거나 드래그로 다중 선택하고, Shift+드래그로 추가하며, 다시 클릭·드래그해 해제할 수 있습니다. 청크·티어·칩앤컷 유형을 지정해 **채택·제외·보류**를 일괄 적용합니다. 채택 시 선택 후보의 최소 표시 면적 이상인 미검토 자동 후보를 같은 유형으로 자동 채택할 수 있습니다. 이미 제외했거나 직접 판정한 후보는 덮어쓰지 않습니다. 탐색이 놓친 균열은 수동 경로로 추가할 수 있습니다.

민감도는 낮음/보통/높음 세 단계입니다. **같은 영역 지도와 분류 체계에서** 다시 탐색하면 지정 영역 안의 기존 채택·제외 판단과 수동 경로를 유지하고, 미검토 후보만 새 검출 결과로 갱신합니다. 지정 영역 밖의 과거 후보는 제거합니다. 영역 지도가 변경되면 결과가 오래된 것으로 표시되며, 재탐색 전에는 검토 상태를 바꿀 수 없습니다. 전체 삭제 버튼은 후보·판정·수동 경로를 지우고 영역 지도와 사진은 유지합니다. 결과는 작업의 `result/cracks/review.json`에 저장되고 작업 삭제 시 함께 지워집니다.

이 방법은 표면 색과 그림자에 민감합니다. 지정한 도형 안의 골부 경계, 숫자 표기, 찢긴 고무가 잘못 검출될 수 있고 밝거나 얇은 균열은 누락될 수 있습니다. 지정되지 않은 스프라켓 홀과 트랙 바깥 영역은 후보에 포함하지 않습니다. 표시된 길이는 영상의 선형 성분에서 구한 **대략적인 길이**이며, 제품 안전 판정이나 균열 깊이 측정이 아닙니다. 특히 철심 노출 여부는 사진만으로 자동 확정하지 않습니다.

## API

- `GET /api/jobs/{id}/cracks`: 저장된 후보와 검토 상태, 영역별 집계 및 영역 지도 변경 여부.
- `DELETE /api/jobs/{id}/cracks`: 해당 작업의 후보·판정·수동 경로를 모두 지웁니다. 영역 지도와 사진은 유지합니다.
- `POST /api/jobs/{id}/cracks/propose`: `{"group_id":"geometry","sensitivity":"normal"}`로 새 후보를 생성합니다.
- `PATCH /api/jobs/{id}/cracks/{candidate_id}`: `{"status":"accepted","damage_type":"tear"}`처럼 검토합니다.
- `POST /api/jobs/{id}/cracks/review-batch`: `{"candidate_ids":["..."],"status":"accepted","damage_type":"chunk","auto_larger":true}`로 다중 판정과 표시 면적 기준 자동 채택을 적용합니다.
- `POST /api/jobs/{id}/cracks/manual`: `{"points":[[x,y],[x,y],...]}`로 놓친 균열 경로를 추가합니다.
- `DELETE /api/jobs/{id}/cracks/{candidate_id}`: 수동으로 그린 균열 경로를 삭제합니다.
