# 손상 검토 작업 공간

전개 사진에서 **사용자가 지정한 영역 안**의 손상 후보를 탐색하고, 청크·티어·칩앤컷으로 자동 분류해 즉시 집계합니다. 이 분류는 사진 기반 검토 초안입니다. 사용자는 사진에서 후보를 클릭해 유형을 바꾸고, 윤곽을 수정하거나 후보를 삭제할 수 있습니다. 사진 위 오른쪽에 유형별 색상 범례를 두고, 옆 패널은 유형별 건수와 영역별 건수·표시 면적(mm²)을 보여줍니다.

## 검출과 분류

1. 거의 검은 연속 픽셀을 핵심 증거로 삼고, 국소 명암 대비와 두 피치 반복 패턴을 보조 신호로 씁니다. 반복되는 홀 가장자리·골부 벽·분필 옆 그림자를 최대한 억제합니다. 짧게 끊긴 선은 중간에도 어두운 홈의 영상 근거가 있을 때만 연결합니다.
2. 검은 핵심부가 드문 뜯김을 위해 같은 위상의 다른 피치와 **색·밝기·질감**을 비교하는 별도 경로를 사용합니다. 다른 고무 색이 덩어리로 모이고 어두운 함몰 경계가 일부 보이는 곳을 후보로 제안합니다. 색상 차이만으로 결손이라고 확정하지 않습니다.
3. 길고 좁은 균열은 검출 윤곽이 **100 mm²(1 cm²) 이상**이어도 티어로 제안합니다. 그 외 덩어리형 손상은 100 mm² 이상이면 청크, 미만이면 칩앤컷으로 제안합니다. 이 면적 경계는 이번 작업의 **운영상 임시 규칙**이며 보편적인 제품 규격이나 손상 깊이 기준이 아닙니다. 사진 한 장으로는 칩·컷·청크의 깊이와 재료 손실량을 확정할 수 없으므로 사용자가 경계와 유형을 수정할 수 있습니다.
4. 결과는 별도 승인 클릭 없이 자동으로 집계됩니다. 과거 `미검토` 데이터도 불러올 때 자동 분류해 표시합니다. 사용자가 지정한 유형·직접 그린 경계는 같은 영역 지도에서 재탐색해도 유지됩니다. 삭제한 후보의 위치는 다시 찾기에서 재생성되지 않도록 기록합니다. 전체 초기화는 후보와 판정 기록을 지우지만 사진과 영역 지도는 유지합니다.

## 사진에서 수정

- **후보 클릭:** 청크·티어·칩앤컷을 선택해 즉시 수정합니다. 잘못 검출된 후보는 **후보 삭제** 하나로 제거합니다. **자동 윤곽 수정**에서 검은색 허용 범위와 경계 여유를 미리보며 조정할 수 있습니다.
- **빈 곳 클릭 또는 드래그:** 검은 연결 영역을 추출하고 미리보기를 확인합니다. 검출이 실패하거나 범위가 맞지 않으면 같은 팝업에서 직접 그리기로 전환합니다.
- **직접 검출 / 직접 그려 수정:** 마우스를 누른 채 손상을 그립니다. 시작점 근처(화면 기준 24px 이내)에서 마치면 닫힌 경계로 인식합니다. 열린 선은 티어, 닫힌 경계는 100 mm² 이상이면 청크, 미만이면 칩앤컷으로 제안합니다. 저장 전 열린/닫힌 상태와 면적·예상 유형을 확인하고 다시 그리거나 취소할 수 있습니다. 기존 후보에서 실행하면 윤곽을 제자리 수정합니다.
- 휠 확대·축소와 휠 버튼 이동은 그리기 중에도 사용할 수 있습니다. 직접 그린 경계는 지정 영역 안에 있어야 하며, 같은 후보를 수정할 때 새 후보로 중복 집계하지 않습니다.

## 한계와 검증

명암과 색·질감 차이는 그림자, 오염, 분필, 조명 변화에서도 발생합니다. 자동 후보는 과검출·누락될 수 있습니다. 개발용 수작업 표본 10개 손상 위치는 모두 후보 윤곽에서 45px 이내였고, 구조 그림자 9곳 중 8곳은 후보가 없었습니다. 이전 면적 우선 분류는 긴 균열을 청크로 잘못 제안할 수 있어 형상 우선으로 수정했습니다. 실제 450 mm 작업의 유형 표본 7건 중 자동 제안은 5건이 사람 표기와 같았고, 남은 2건은 칩앤컷을 티어로 제안했습니다. 이 표본은 의도적으로 고른 곳이며 전체 사진의 정확도 추정치가 아닙니다. 깊이, 철심 노출, 제품 안전 여부는 자동 판정하지 않습니다. `tests/test_cracks.py`는 검은 핵심부, 반복 구조, 지정 영역 제한, 재탐색, 색·질감으로 찾은 소형 결손, 마우스 선·닫힌 경계의 면적 분류와 기존 후보의 제자리 수정을 검증합니다. `frontend/tests/stroke.test.mjs`는 열린 선과 시작점 근처로 돌아온 경계의 구분을 검증합니다.

## 용어 근거와 한계

[Bridgestone/Firestone 러버트랙 운영 매뉴얼](https://www.bridgestone.com/products/diversified/rubbertrack/pdf/Tracks-Operating-Manual-USpdf.pdf)은 abrasion·erosion·chunking을 한 손상 군으로 설명하면서 트레드 바의 chipping을 그 외관으로 제시하고, flex/base cracking은 별도로 설명합니다. [Nissitrac의 러버트랙 FAQ](https://nissitrac.com/faqs/)도 기계적 절단·찢김과 마모·침식·청크 손상, 굴곡 균열을 외관과 원인으로 구분합니다. 두 자료는 **칩과 청크를 1 cm²로 구분하지 않습니다**. 따라서 현재 세 유형과 100 mm² 경계는 현장 검토를 위한 작업 분류이며, 표준 용어로 표시해서는 안 됩니다. 특히 닫힌 윤곽의 칩·청크 구분은 면적만 반영한 임시 제안입니다.

## API

- `GET /api/jobs/{id}/cracks`: 후보 윤곽, 자동·사용자 결정 출처, 유형 및 영역별 집계.
- `POST /api/jobs/{id}/cracks/propose`: 지정 영역에서 다시 검출·분류.
- `POST /api/jobs/{id}/cracks/trace`, `/trace/apply`: 클릭·드래그한 검은 연결 영역의 미리보기와 적용.
- `POST /api/jobs/{id}/cracks/manual`: `{"points":[[x,y],...],"closed":false,"candidate_id":null}`. `closed:true`면 닫힌 경계이고 `candidate_id`를 주면 기존 윤곽을 제자리 수정합니다.
- `PATCH /api/jobs/{id}/cracks/{candidate_id}`: 유형을 사용자 결정으로 수정.
- `DELETE /api/jobs/{id}/cracks/{candidate_id}`: 후보 삭제 및 재탐색 억제.
- `DELETE /api/jobs/{id}/cracks`: 이 작업의 후보·판정 기록 전체 초기화.
