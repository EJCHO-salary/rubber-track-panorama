# 러버트랙 손상 분석 백엔드 — 1차 구현과 다음 단계

## 입력과 처리 결과

전개 완료된 `panorama.png`(없으면 `panorama.jpg`)와 `quality_report.json`의 폭·피치·pixels/mm를 입력으로 사용합니다. 길이 방향은 이미지 x축이며, x축의 한 피치는 `pitch_mm × pixels_per_mm`입니다. y축은 트랙 폭입니다. 새 작업은 전개가 끝나면 손상 분석을 자동 실행합니다. 기존 작업은 `POST /api/jobs/{id}/damage`로 실행하거나 재분석합니다. 결과는 같은 작업의 `result/damage/`에 저장되므로 작업 삭제 시 원본 사진과 함께 삭제됩니다.

로컬 샘플을 직접 재분석할 때는 `.venv/Scripts/python.exe -m track_unwrap.damage --result output/case2`처럼 실행합니다. 450/86 샘플은 `--result output/result`입니다.

- `analysis.json`: 영역 면적, 청크·티어 후보의 원본 이미지 좌표, 포함 여부, 영역별 및 총합 집계, 자동 분석의 한계.
- `zone_mask.png`: 분석 해상도의 픽셀 라벨. `1=트레드`, `2=골부`, `3=스프라켓 홀`, `4=심금 매설 중앙부`.
- `anomaly_mask.png`: 반복 패턴에서 벗어난 후보 픽셀. 최종 손상 판정과 동일하지 않습니다.
- `zone_review.jpg`, `candidate_review.jpg`: 전체를 4구간으로 나눈 검토용 오버레이. 후보 검토 화면에서는 JSON의 원본 좌표 다각형을 원본/Deep Zoom 위에 그리는 편이 정확합니다.

영역 분할은 여러 피치의 명도 중앙값으로 표준 패턴을 만든 뒤 중앙 홀의 상하 경계와 어두운 직사각형, 바깥쪽 반복 골을 찾습니다. 자동 분할이 맞지 않으면 사용자가 **한 피치의 영역 다각형**을 지정합니다. 백엔드는 다각형을 피치 위상으로 환산해 관측된 전 길이에 반복합니다. 하나의 패턴에 여러 조각이 있으면 여러 다각형을 보냅니다. 입력 좌표는 다운로드용 원본 `panorama.jpg`의 픽셀 좌표입니다.

후보 검출은 각 피치를 표준 패턴과 비교하고 피치별 밝기 차이를 제거한 뒤, 충분히 다른 어두운 부분을 연결요소로 찾습니다. 기본 설정에서 청크는 **100mm²(1cm²) 이상**, 티어는 **길이 10mm 이상·폭 8mm 이하·종횡비 4 이상**입니다. 티어 기준은 사용자 정의가 없으므로 조정 가능한 초기값입니다. 같은 위치에서 반복해서 보이는 후보는 설계 형상 또는 정합 오차로 보고 기본 집계에서 빼되, 검토 목록에서는 남깁니다. 청크와 티어가 겹치면 청크 픽셀을 티어 검출에서 제외해 이중 집계를 줄입니다. 밝은 이상은 분필 표시의 오탐을 줄이기 위해 기본으로 제외하며, 설정으로 활성화하거나 수동으로 추가할 수 있습니다.

손상률은 `선택된 후보 면적 / 해당 영역의 보이는 면적 × 100`입니다. 총합도 네 영역의 보이는 면적을 분모로 사용합니다. 이는 **사진상 이상 면적 비율**이며 재료 손실 깊이, 내부 파손, 구조 안전성 또는 실제 사용 가능 여부의 판정이 아닙니다. 홀 내부의 보이는 면적 역시 지정된 네 영역 체계에 따라 분모에 포함됩니다. 폭·피치로 보정한 명목 치수이므로 독립 실측 없이 절대 면적 정밀도를 보증하지 않습니다.

## API 사용

`GET /api/jobs/{id}/damage`는 분석 결과를 반환하고, 없으면 404입니다. `POST /api/jobs/{id}/damage`는 동기식 재분석입니다. 이전 영역 보정과 사용자가 검토한 후보의 포함/제외는 기본으로 유지됩니다. 동시 재분석은 409를 반환합니다. `GET /api/jobs/{id}/damage/files/{name}`에서 검토 이미지와 마스크를 받습니다. 로컬 샘플은 `GET /api/samples/case1/damage`, `GET /api/samples/case2/damage` 및 같은 경로의 `/files/{name}`으로 읽습니다.

```json
POST /api/jobs/{id}/damage
{
  "zone_seeds": [
    {"zone": "sprocket_hole", "polygon": [[610, 480], [690, 480], [690, 640], [610, 640]]}
  ],
  "config": {
    "chunk_min_area_mm2": 100,
    "tear_min_length_mm": 10,
    "tear_max_width_mm": 8,
    "tear_min_aspect": 4,
    "include_bright_anomalies": false
  }
}
```

영역 이름은 `tread`, `groove`, `sprocket_hole`, `embedded_core`입니다. `zone_seeds`를 생략하면 이전 보정을 유지하고, 빈 배열을 보내면 초기화합니다. 임계값 설정도 생략하면 이전 값을 유지합니다. API가 반환하는 후보의 `id`, `polygon`, `bbox_xywh`, `zone`, `mode`, `area_mm2`, `included`, `reviewed`, `auto_reason`을 검토 UI에 사용합니다.

```json
PATCH /api/jobs/{id}/damage/candidates/{candidate_id}
{"included": false}
```

같은 엔드포인트에 `true`를 보내면 재선택합니다. `PATCH /api/jobs/{id}/damage/modes`에 `{"active_modes":["chunk"]}` 또는 `{"active_modes":["tear"]}`를 보내면 해당 모드만 집계합니다. 둘 다 보려면 `{"active_modes":["chunk","tear"]}`입니다. `POST /api/jobs/{id}/damage/candidates`에 `{"mode":"tear","polygon":[[x,y],...]}`로 누락 후보를 수동 추가할 수 있습니다. 수동 후보는 재분석 후에도 유지됩니다.

## 현재 샘플과 검증 상태

로컬 두 샘플에서 분석이 끝났고 영역·후보 오버레이를 육안으로 확인했습니다. 230/48 샘플은 중앙 홀 반복을 대체로 잡지만, 몇몇 트레드 음영이 손상 후보로 남습니다. 450/86 샘플은 홈 가장자리·그림자 오탐이 더 많습니다. 결과 JSON의 `review_status=unverified_auto_candidates`를 유지하며, 현재 자동 손상률을 제품 품질 판정에 사용해서는 안 됩니다. 정답 영역 및 손상 라벨이 없으므로 정밀도·재현율도 아직 산출할 수 없습니다.

다음 개발 단계는 다음 순서가 적절합니다.

1. 검토 UI에서 후보 다각형의 선택/해제, 새 후보 그리기, 한 피치 영역 보정, 원본 확대 비교를 구현합니다. 전개 이미지 위의 좌표 변환과 키보드 단축키를 포함합니다.
2. 두 샘플과 다른 촬영 조건의 제품에서 영역 및 청크·티어를 실제 사람이 라벨링합니다. 분필, 먼지, 그림자, 연결선도 **비손상**으로 라벨링합니다.
3. 제품 단위로 학습·검증 데이터를 나누고 영역 분할과 손상 인스턴스 분할 모델을 학습합니다. 픽셀 IoU, 후보 정밀도·재현율, 물리 면적 오차를 영역별/제품별로 평가합니다. 같은 제품의 인접 피치를 학습·검증에 나누면 성능이 부풀려지므로 피합니다.
4. 모델을 현재 후보 생성 인터페이스에 연결합니다. 모델 버전·임계값·사용자 수정 내역을 보고서에 기록하고, 신뢰도가 낮은 후보를 검토 순서 앞에 배치합니다.

현재 로직은 학습 데이터 없이 검토 화면을 시작하기 위한 기준선입니다. 반복 피치와 실물 단위를 사용하는 공통 계약은 학습 기반 검출기로 바꾸더라도 유지할 수 있습니다.
