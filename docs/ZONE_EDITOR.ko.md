# 영역 편집기

전개 사진을 만든 뒤 `/jobs/{id}/analysis`에서 영역을 직접 지정합니다. 백엔드는 자동 영역 분류 및 청크·티어 검출을 실행하지 않습니다. 경계 보조 선택은 사용자가 먼저 그린 다각형 주변에서 GrabCut으로 윤곽을 제안할 뿐이며, 사용자가 **닫힌 도형 저장**을 누르기 전에는 분류 데이터를 바꾸지 않습니다.

## 데이터 구조

- **분류 체계**: 형상별, 제조공법별 등 사용자가 이름을 정하는 최상위 레이어. 여러 체계가 같은 픽셀에서 겹쳐도 각각 독립적으로 보존됩니다.
- **세부 섹션**: 각 체계 안에 여러 개를 만들고 이름과 색을 수정할 수 있습니다. 트레드·골부 등의 초기 명칭은 예시입니다.
- **기본 섹션**: 한 체계에서 어떤 형상도 그리지 않은 픽셀을 채울 섹션. 처음에는 중립적인 '미지정'입니다. 기본 섹션을 변경할 수 있으며 마스크에는 빈 픽셀이 없습니다. 이는 미지정 픽셀을 자동 인식했다는 뜻이 아닙니다.
- **형상**: 하나의 세부 섹션에 속하는 다각형. 골부처럼 같은 섹션에 여러 형상을 둘 수 있습니다. `repeat=true`이면 `repeat_pitches`(1~2000)에 지정한 피치 간격마다 적용됩니다. 기본 `independent` 방식은 각 도형의 피치 위상을 보존하면서 **모든 도형을 각각** 반복합니다. 긴 골부와 짧은 골부가 번갈아 나타나면 두 도형을 그려 각각 2피치 반복으로 설정합니다. `examples` 방식은 **같은 쪽**에 같은 형상의 대체 예시를 여러 위치에 그린 경우에 사용하며, 각 반복 구간에 가장 가까운 예시 하나를 적용합니다. 중앙선 반대편에 180° 회전시킨 형상은 별도 쪽으로 취급해 양쪽 모두 반복합니다. `repeat=false`이면 그린 위치에만 적용됩니다. 같은 분류 체계에서 겹치는 형상은 목록에서 나중에 저장된 형상이 앞의 형상을 덮습니다.

점을 찍고 **첫 점을 다시 누르면** 도형이 닫힙니다. 다음 사진 클릭부터 같은 섹션의 다른 도형을 시작하므로 골부 여러 개를 한 번에 지정할 수 있습니다. 첫 점이 보이지 않으면 **현재 도형 닫기**를 누릅니다. 닫힌 도형은 사진 위의 점을 바로 끌어 수정하거나 우클릭으로 점을 삭제할 수 있습니다. 목록의 **점 추가**를 누르면 도형을 다시 열어 새 점을 넣을 수 있습니다. 저장된 도형의 편집 버튼도 닫힌 도형을 조정하는 상태로 엽니다. 편집 중 반복 간격을 바꾸면 아직 저장하지 않은 닫힌 도형 모두에 적용됩니다. 저장된 도형은 섹션별 일괄 간격 변경 기능을 사용합니다. 모든 도형을 닫은 뒤 한 번에 저장합니다. 편집 중에도 휠로 확대·축소하고 **휠 버튼을 누른 채 드래그하면** 사진을 이동할 수 있습니다. 휠 버튼 이동은 도형의 점 위에서도 작동하고 새 점을 만들지 않습니다. Ctrl+Z는 현재 열린 형상의 마지막 점 조작을 되돌립니다. 분류 체계와 섹션은 이름 수정, 추가, 삭제할 수 있습니다. 섹션 삭제 시 참조 형상도 지워지고 기본 섹션이 삭제된 경우 다른 섹션을 기본값으로 지정합니다.

반복 도형을 하나 닫은 뒤 **180° 후보**를 누르면 상·하 반대쪽의 회전 대응 형상을 최대 3개 제안합니다. 사진에서 측정한 피치 기준점을 정규화한 뒤, 사용자가 설정한 반복 간격(1~8피치)에 걸쳐 양쪽의 모서리 패턴을 비교합니다. 선택한 후보는 주황색 점선으로 미리 보이며, **선택 후보 도형에 추가**를 누르면 같은 섹션의 편집 가능한 닫힌 도형이 됩니다. 최종 **한 번에 저장** 전에는 영역 문서가 바뀌지 않습니다. 표시된 유사도는 확률이 아니라 사진의 모서리 영상 상관도입니다. 훼손·조명·비대칭 형상에서는 낮을 수 있으므로 수동으로 위치와 윤곽을 확인해야 합니다. 중앙선을 가로지르는 도형은 이 보조 기능의 대상이 아닙니다.

저장 목록은 세부 섹션별로 묶습니다. 예를 들어 골부 도형이 두 개여도 목록에는 **골부 · 도형 2개** 한 줄만 보입니다. 펼치면 1·2번 도형을 각각 편집하거나 삭제할 수 있고, 묶음의 편집 버튼은 두 도형을 한 번에 열어 위치를 조정합니다. 내부 저장 자료는 도형별로 유지하므로 서로 다른 위상과 반복 간격을 보존합니다.

## API 및 산출물

- `GET /api/jobs/{id}/zones`: v3 영역 문서 조회. 기존 전개 작업에는 최초 접근 시 편집 가능한 기본 체계를 생성합니다.
- `PUT /api/jobs/{id}/zones`: `{"groups":[...],"shapes":[...]}` 문서 전체 저장. 서버가 ID, 섹션 참조, 좌표, 반복 형상의 반복 간격 너비를 검증합니다.
- `POST /api/jobs/{id}/zones/assist`: `{"polygon":[[x,y],...]}`을 받아 제안 윤곽과 `changed`를 반환합니다. 저장은 하지 않습니다.
- `POST /api/jobs/{id}/zones/half-turn`: `{"polygon":[[x,y],...],"repeat_pitches":2}`를 받아 대칭 후보의 다각형·영상 유사도·피치 위상을 반환합니다. 저장은 하지 않습니다.
- `GET /api/jobs/{id}/zones/groups/{group_id}/overlay.png`: 해당 체계의 반투명 오버레이.
- `GET /api/jobs/{id}/zones/groups/{group_id}/mask.png`: 해당 체계의 픽셀 라벨. 각 체계의 `sections` 순서대로 1부터 부여합니다.
- `GET /api/jobs/{id}/zones/groups/{group_id}/authored.png`: 사용자가 그린 도형이 실제로 배치된 픽셀(255)과 기본값으로 채운 픽셀(0)의 구분.

원본 좌표는 `panorama.png`를 기준으로 합니다. 마스크와 오버레이는 메모리 비용을 제한하기 위해 최대 약 200만 픽셀의 작업 해상도로 생성합니다. 응답의 `image_size_wh`, `pitch_px`, `nominal_pixels_per_mm`, `working_pixels_per_mm`와 `group_metrics`를 이용해 화면에 표시합니다. 면적 `mm²`는 정규화된 이미지의 명목 픽셀/mm를 사용한 추정값이며 실물 계측 보증값은 아닙니다.

마스크의 기본 섹션과 직접 그린 형상이 같은 이름이어도 `authored.png`에서 구분합니다. 오버레이는 기본 채움은 연하게, 직접 지정된 영역과 그 경계는 진하게 표시합니다. `group_metrics.explicit_areas_mm2`는 직접 지정된 섹션별 면적이며, `fallback_area_mm2`는 실제로 도형이 닿지 않아 기본 섹션으로 채워진 면적입니다. 하나의 도형 배치 계산에서 라벨 마스크와 직접 지정 마스크를 함께 그려 두 결과가 어긋나지 않게 합니다.

반복 배치는 일정한 `pitch_px`를 더하는 대신, 사진 중앙의 반복되는 어두운 홀에서 실제 피치 기준점(`pitch_anchors_x`)을 측정하고 기준점 사이를 선형 보간합니다. 기준점 탐지가 불안정한 사진은 `pitch_anchor_source=nominal`로 표시하고 명목 피치 간격을 사용합니다. 측정 기준점과 반복 배치에는 영상의 손상 여부 또는 영역 명칭 추론이 개입하지 않습니다.

영역 산출물은 작업의 `result/zones/`에 저장됩니다. 작업 삭제 시 업로드 원본과 함께 지워집니다. 기존 손상 분석 문서의 사람이 그린 `zone_seeds`만 최초 초기화 시 옮깁니다. 자동 검출 후보와 자동 영역은 옮기지 않으며 기존 `result/damage/`는 갱신하지 않습니다. 앞으로 손상 분석을 추가한다면 사람이 확인한 v3 영역 문서를 입력으로 사용해야 합니다.
